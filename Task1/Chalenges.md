# Проблемные зоны и риски в текущей архитектуре

## 1. Сложность миграции с легаси DWH
- Описание: DWH построен на устаревшем Microsoft SQL Server 2008, с большим количеством бизнес-логики и старым
интерфейсом (Power Builder). Миграция данных и логики на новые платформы требует значительных ресурсов и времени.
- Риски: Возможны ошибки при переносе данных, временное снижение доступности, необходимость переписывать бизнес-логику.

## 2. Слабая масштабируемость старых компонентов
- Описание: Текущий DWH и интеграционная шина (Apache Camel) не рассчитаны на современные объёмы данных и высокую
нагрузку.
- Риски: Медленная генерация отчётов, узкие места при интеграции новых бизнесов, невозможность горизонтального
масштабирования.

## 3. Сложность интеграции новых бизнесов
- Описание: Новые компании (фармацевтика, электроника) могут использовать разные форматы и стандарты данных. Интеграция
через существующую шину требует значительных доработок.
- Риски: Рост затрат на интеграцию, увеличение времени вывода новых сервисов на рынок.

## 4. Отсутствие единого подхода к управлению доступом и безопасности
- Описание: Не определены чёткие правила разграничения доступа между доменами (например, финтех не должен видеть мед.
данные).
- Риски: Возможные нарушения законодательства (например, ФЗ-152), утечки данных, штрафы.

## 5. Зависимость от устаревших технологий
- Описание: Использование Power Builder, старых версий SQL Server, монолитных решений.
- Риски: Дефицит специалистов, отсутствие поддержки, невозможность быстро внедрять новые функции.

## 6. Сложность поддержки и развития BI/аналитики
- Описание: BI-система сильно завязана на DWH, отчёты строятся медленно, сложно внедрять новые метрики и отчёты.
- Риски: Низкая удовлетворённость бизнес-пользователей, потеря конкурентных преимуществ.

## 7. Отсутствие стандартизации обмена данными
- Описание: Каждый домен может использовать свои форматы, нет единого API/шаблонов интеграции.
- Риски: Рост технического долга, сложность поддержки, дублирование данных.
